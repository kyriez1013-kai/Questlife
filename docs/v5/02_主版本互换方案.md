## Git 差异和保护

- 分支 `feature/v5-ui` 从 `ce2deaa` 开始；A–F 只本地提交。
- 实时远端快照：`main=c8c4387f302af5ef7dd05eaab2d177f6a000447b`，`release/questlife-v1=b74072a73d2fe2c33bd6446d2e0acb32122949bd`。本地 release 为 `65490de`，不能把本地引用当成远端最新。
- 在 E 提交 `b901b6a` 时，本地 main 与该分支左右差异为 1 / 380 个提交，含长期既有分支历史，不是本轮新增 380 个提交。远端合并是否冲突只能在 G 临时 clone 的最新引用上确定。
- G 在仓库外临时 clone 做两次合并：V5 → 远端 release → 远端 main。冲突立即停止，不自动选 ours/theirs；合并后运行时代码必须与已部署验收版本一致，否则停止，重新验收。
- 原 main 打 `archive/main-before-v5`；tag 已存在则停止。使用普通 atomic push，不 force，不改主工作目录的五处改动。
- 推送前断开两个 Vercel 项目的 Git 自动部署，防止 main 推送意外覆盖旧存档或候选已验收构建。此动作会打印在确认清单中；之后仍用 committed archive 的 `deploy:candidate` 发布，不自动恢复 Git 部署。

## 两条命令

`npm run promote:main` / `npm run rollback:main` 均先显示步骤，交互输入 `yes` 才做任何远端变更。**只有 Kyrie 明确说“确认互换”后才运行 promote。** 本轮仅语法与 `--plan` 检查，没有执行互换。

Promotion：验证项目及候选版本 → 临时合并与版本比对 → 原 main 标签 → 停自动部署 → 原子推 tag/release/main → 移域名 → 校验域名 version.json。数据库与账号完全不迁移。

Rollback：临时 clone 从归档树创建恢复 main 的新提交，不改写历史；release 不回退；域名移回旧项目，比较旧存档 HTML。旧、新账号数据不会随域名搬家，回滚前后应先确认当前站点账号。

失败保留 `/tmp/questlife-v5-main-*` 的 before/result 记录，Git 与域名操作跨服务无法原子化；遇到部分完成不要重复运行 promote，先检查记录再用 rollback。脚本不删除部署、项目、数据库或用户数据。
