## 0. 产品决策：先写进仓库，再开工

在仓库新建 `docs/PRODUCT_DECISIONS.md`（不超过一页），写入下面 9 条。以后所有指令都以它为准，只有用户本人能修改。

1. **当前优先级：先让用户本人每天愿意用。** "任何人都能完整使用"放在之后。这一条取代 2026-10-14 的"先完整交付给任何人"。
2. **视觉以第五版为准。** 之后的视觉修改只接受"具体元素 + 具体问题"，不再整页重做。
3. **今日页的核心是"状态 → 行动"。** 状态是 `todayCommand` 的输入，`todayCommand` 仍是今日唯一的主动作权威。
4. **首屏文案 = 一句动作 + 一句短理由。** 不确定性用来源标签表达（规则判断 / 通用依据 / 你的记录 n 次），详细依据点开才看。首屏不堆免责说明。
5. **每增加一项主动记录，都要说明它改变了哪个判断或建议。** 说明不了就不加。
6. **任何日程改动：预览 → 用户确认 → 应用 → 可撤销。** 永不自动改日程。
7. **复杂模型进入决策之前，必须在未来数据上优于"个人基线 + 简单规则"。**
8. **近期交付形态：Web/PWA 是日用主力。** 新版本验收后接管主版本的自定义域名和 GitHub `main`；旧主版本保留为存档。 原生 iOS 暂不追求视觉一致，等用户决定是否购买开发者账号。健康和日历数据经 iOS 快捷指令同步。
9. **30 天检验：** 签到天数、状态改正率、是否出现至少一条改变了安排的"对你来说"结论。

## 4. 阶段 B：今日页（最重要）

### 页面结构（从上到下）

日期头 → 记录框 → **此刻状态条** → **现在做什么（主卡）** → 后续安排 → 最近执行 → 底栏

**删除：** 右上角时钟按钮；"3 项安排 / 0 条执行"统计行（挪进"后续安排"标题行）；主卡里的"关联方向"行（与标题下的路径重复）；"此刻精力"行（并入状态条）。

### B1. 记录框
提示语改为"随手记一句…"。行为不变：沿用现有 Capture → 解析 → 确认链路。语音用系统键盘的听写，不另做。

### B2. 此刻状态条（替换原统计行的位置）

| 情况 | 显示 | 交互 |
|---|---|---|
| 未签到 | 一行："现在怎么样？"，右侧"记一下" | 点击后在条内展开两排 5 档：精力（没电 … 很足）、紧绷（很松 … 很紧）。第二次点选后自动保存，等 ACK 后收起。选填的"挂着的事""对眼前这件事"放在收起后的"补充"小链接里，默认不展开 |
| 已签到 | "过载 · 挂着的事较多 · 09:20"，右侧"不是这样" | 点主体打开依据 Sheet；点"不是这样"可改正 |
| 签到超过 3 小时 | "09:20 · 过载 · 现在呢？"，样式变弱 | 不弹窗，点击重新签到 |

手机签到和手表快捷指令签到（阶段 E）显示在同一条里。

**依据 Sheet：**
- 一句理由。
- 四个估计维度，各一个小条，并标注"依据充分 / 不足"。没有数据的维度显示"没有数据"，不估：
  - 清醒度 ← 精力 + 睡眠相对个人常态 + 当前时段
  - 认知负荷 ← 紧绷 + 挂着的事 + 过去 3 小时切换过的不同目标数（标明是代理指标）
  - 情绪压力 ← 紧绷（以及选填的情绪）
  - 身体恢复 ← 昨天的训练量、静息心率/HRV 相对个人基线（有数据才算）
- 用到了哪些信号、没用到哪些信号。
- 来源标签：规则判断 / 通用依据 / 你的记录 n 次。
- "不是这样"：改正后保存为改正记录，以后的统计按改正后的类型算。

### B3. 主卡「现在做什么」

把 `todayCommand` 的输出渲染成第五版"接下来"卡的样式。新增输入：当前状态类型、下一个任务的"需要的状态"（阶段 C）。**未签到时，todayCommand 的输出必须和现在完全一致**，用测试证明。

| 情况 | 卡片标签 | 主标题 / 副标题 | 按钮 |
|---|---|---|---|
| S1 有日程，状态匹配或未签到 | 接下来 | 下一个日程的名称；目标/模块路径、时间、时长 | 开始 · 记录实际执行 |
| S2 状态与下一个任务不匹配 | 建议先做 | 调节动作（见下表）；副标题如"原型设计顺延到 10:30（需你确认）" | 按建议调整 · 照原计划 |
| S3 今天没有日程 | 现在建议 | todayCommand 自己的建议（现有逻辑） | 开始 |
| S4 动作进行中 | 进行中 | 名称 + 已进行时间 | 完成 |
| S5 回访到期 | （卡片顶部一行） | "刚才清空脑子后，现在精力？" | 五档一键，可忽略 |

- **按建议调整** → 由现有重排逻辑生成调整方案 → 现有 planPatch 预览（必须检查冲突）→ 用户确认 → 应用 → 可撤销。
- **照原计划** → 记录为一次"用户选择原计划"的决策（以后用于比较），今天不再就同一任务提示。
- **S4 完成** → 一屏完成：实际分钟（默认用计时结果，可改）、"比预想 轻松 / 差不多 / 更难"一键、可选一句备注。保存等 ACK。在执行记录的 payload 里新增可选字段：计划分钟、实际分钟、主观难度对比（schemaVersion 兼容）。这是"校准"数据：比较用户的预估和实际，至少 10 条后才在分析里显示描述。
- **S5** 在选择调节动作后 20–40 分钟出现，或用户下次打开时出现。

**匹配规则**（写成纯函数并完整测试；任务缺少"需要的状态"时按"未知"处理，不判不匹配）：

| 当前状态 ＼ 任务需要 | 深度专注 | 轻量 | 体力 | 恢复 | 社交 |
|---|---|---|---|---|---|
| 平静有劲 | 匹配 | 匹配 | 匹配 | 匹配 | 匹配 |
| 紧绷有劲 | 匹配（依据里提示可先快走 10 分钟降紧绷） | 匹配 | 匹配 | 匹配 | 匹配 |
| 燃料不足 | **不匹配 → 降级或先恢复** | 匹配 | **不匹配 → 恢复** | 匹配 | 匹配 |
| 过载 | **不匹配 → 先清空脑子 10 分钟** | 匹配 | 匹配 | 匹配 | **不匹配 → 先清空脑子** |
| 低唤醒 / 回避 | **改为"先做 5 分钟：<任务名>"**（不换任务，只缩小开始） | 匹配 | 匹配 | 匹配 | 匹配 |
| 说不准 | 不改变 | 不改变 | 不改变 | 不改变 | 不改变 |

**文案约束：** 主标题不超过 14 个字，副标题不超过 24 个字。首屏不出现"可能 / 无法确定 / 尚无证据"这类长免责，统一用来源标签表达。

**G2. 准备两条命令，但本轮不执行：**
