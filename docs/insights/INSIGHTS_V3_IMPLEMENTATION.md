# Insights V3 Implementation

## Surface architecture

Insights V3 is isolated behind `questlife_v11_ui=insights-v3`. Removing that
query value restores the existing Insights surface immediately.

The presentation is split into:

- `insightsV3Source.ts`: explicit bundle loading, Product Contract validation,
  fixture provenance checks, cache, and debug-only timing;
- `insightsV3Presentation.ts`: deterministic labels, formatting, range
  selection, and Product Contract field selection;
- `InsightsV3Screen.tsx`: watchlist, active instrument, controls, compact
  interpretation, and tool routing;
- `InsightsV3Watchlist.tsx` and `insightsV3WatchlistPreferences.ts`: the
  existing terminal watchlist preference contract, including add/remove,
  reorder, pinning, and fixture-isolated review preferences;
- `InsightsV3Chart.tsx`: rendering of upstream points, ranges, candles, events,
  and comparison series;
- `InsightsV3Analysis.tsx`: Drivers, Similar, Recovery, Scenario, Analyst,
  Evidence, and Events presentation;
- `InsightsV3Sheet.tsx`: shared mobile and desktop analysis layer.

The App remains a `validate -> map -> render` consumer. It does not calculate
references, changes, OHLC candles, associations, analogues, or scenarios.

## Product Contract path

- Contract: `questlife.quant.product.v1`
- Schema hash: `da7bd3987a9343c72cb37f2edd4dbc81b604e655d4b915c9f85949f001632335`
- Validator: `src/quant-product/quantProductContract.ts`
- Lossless adapter: `src/quant-product/quantProductV1Adapter.ts`
- Review bundles: `src/quant-product/fixtures/`

At this stage the App repository has no authenticated runtime read endpoint for
an owner Product Bundle. The ordinary Insights V3 route therefore shows an
honest unavailable-source state. It does not replace the missing endpoint with
frontend statistics. Deterministic fixtures load only through the explicit
`quantProductFixture` review parameter and must be synthetic-only with no real
user data.

## Loading strategy

The V3 screen and Lightweight Charts are lazy web chunks. Compact bundles load
first. Full history is fetched only when the user opens an instrument history
or a tool that requires series or interpretation detail. Parsed results are
cached by fixture and phase. A detail failure preserves the validated compact
summary.

## Evidence boundary

- **Fact** is shown from validated latest, reference, change, coverage, event,
  point, range, or candle fields.
- **Inference** is shown only from a PRODUCT_ELIGIBLE interpretation artifact.
- **Recommendation** is not generated by Insights V3.

Drivers are labelled as observational candidates. Similar periods do not claim
mechanism. Recovery is historical analogue evidence, not a forecast. Scenario
branches are historical comparisons, not causal estimates. Analyst exposes
contract-declared chart operations and is not an open-ended chat surface.

## Sparse-data behaviour

- zero observations: no fake instrument or chart;
- one observation: one recorded point, no trend or false precision;
- early history: latest value and forming evidence only;
- comparable history: upstream reference and factual change where present;
- mature history: supported chart and analysis tools become available.

Missing values are never treated as zero. Plans and actual execution remain
separate. Review, QA, debug, and synthetic provenance never masquerade as owner
evidence.

## Research firewall and future inputs

Research-only forecasts, latent-state estimates, change-point outputs, causal
claims, Bayesian challengers, deep-learning outputs, and composite personal
scores are not rendered. Their research assets remain untouched.

Future Health or wearable observations can enter through the same canonical
Product Contract after a separate ingestion and eligibility implementation.
Insights V3 does not connect HealthKit, Apple Health, Google Fit, or wearables.

## Current integration debt

The App repository does not yet expose an authenticated runtime Product Bundle
read endpoint. The ordinary V3 route therefore abstains instead of rebuilding
Quant statistics in the frontend. Explicit fixture routes are synthetic review
surfaces only and are namespaced away from real watchlist preferences.

## V3.1 personal intelligence product layer

V3.1 keeps the V3 chart, ranges, tool architecture, Product Contract, and
research firewall unchanged. It adds a deterministic presentation layer that
makes the active instrument personal and immediately legible before the
Watchlist:

- current reading, recent personal reference, change, and evidence are grouped
  around the active instrument;
- Watchlist remains instrument navigation and no longer leads the hierarchy;
- one compact Analyst cue may route to Drivers, Similar, historical Recovery,
  or evidence, using only the corresponding validated artifact for the active
  instrument;
- Drivers retain support, counterexamples, independent periods, and the
  observational-not-causal boundary in user-facing language;
- Similar, Recovery, and Scenario describe personal historical evidence without
  implying recurrence, forecast, causality, or a recommended action;
- population references, when explicitly provided by the Product Contract, are
  labelled as population references rather than personal history.

The frontend still performs no statistical inference. The mapping is strict,
deterministic, target-instrument scoped, and abstains when the relevant
interpretation artifact is missing.
