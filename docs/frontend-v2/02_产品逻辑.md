# 02 产品逻辑（一页纸）

## 核心价值（我的定义）

> **用最少的输入，看清自己每天的状态和行动，并得到下一步该做什么。结论诚实：数据不够时直接说"还不够"，并说还差什么。**

不是"目标管理系统"，不是"量化终端"。目标/技能/模块是**为了让一句话记录能被归类**的背景结构，不该是用户进来要先搭的东西。

## 每天的使用循环

```
打开 Today ──▶ 3 秒读懂：我现在状态如何 + 下一步做什么
     │
     ▼
 去做事 ──▶ 回来一句话记录（≤10 秒，一次确认）
     │
     ▼
 Today 立刻变化（状态/今日记录/证据进度 +1）──▶ "再记 N 天，就能看你的睡眠与精力有没有关系"
     │
     ▼
 明天再来
```

循环里只有 **三个动作**：看（Today）、记（Capture）、确认（保存 ACK）。凡是不在这三个动作上的功能，都不该占首屏。

## 现有功能 vs 这个循环

| 功能 | 服务循环？ | v2 处理 |
|---|---|---|
| Today 决策结论 + `todayCommand` | 是（"看"） | 保留，重做版式；`todayCommand` 仍是数据权威 |
| 一句话 Capture + AI/本地解析 + 确认 | 是（"记"） | 保留并提到首屏常驻；新增 3 种失败界面 |
| 状态打卡（1–5） | 是（给 Today 提供"我现在怎样"） | 保留，改成首屏一键 5 档 |
| 持久化 ACK / 失败重试 | 是（可信） | 沿用现有 `waitForLocalWrites` 链路，界面重做 |
| 证据等级 / "还差什么" | 是（诚实） | 保留，换成人话（不再显示 "S0/S2"） |
| 今日计划（日程块） | 部分 | Today 里最多显示下一项；完整日程放二级 |
| 快捷记录（最近/此刻日程建议） | 是（降低输入成本） | 保留，改成输入框上方的 chip，常驻 |
| 目标 / 模块 / 技能树管理 | 否（结构维护） | 降到二级入口（"我的 → 目标与技能"），不删 |
| 技能库、技能详情、模块表单 | 否 | 二级 |
| 洞察：Quant 终端（K 线、个人市场、对比/指标/分析/更多） | 否（读取成本极高） | 降到"洞察 → 高级"；默认展示结论卡 + 证据等级 |
| Adaptive Decision 工作区、Schedule 提案确认 | 部分 | 二级（有日程提案时 Today 只出一行入口） |
| Dashboard 布局编辑（Control Center 遗留） | 否 | 不出现在 v2 |
| Debug 面板、fixture 路由、stage0/1/2 | 否 | 保持在旧 flag 后面，v2 不引用 |
| 账号与同步、云端 AI 开关 | 间接（决定能否用 AI 解析） | 放"我的"，首用不强求；Capture 里按需引导 |
| 日程月/年视图 | 否 | 二级 |

## 建议隐藏到二级入口（不删代码，只降低可见度）

1. 目标/模块/技能管理 → "我的 → 目标与技能"
2. Quant 终端、图表工具栏 → "洞察 → 高级"
3. 日程完整视图 → "今天 → 今日计划 → 全部"，以及 Tab "日程"保留但降权
4. 技能库、Dashboard 布局、Debug、Adaptive Decision 工作区 → "我的 → 高级"

## 信息架构结论

v2 用 **4 个 Tab：今天 / 日程 / 洞察 / 我的**。Quest（目标）并入"我的"，因为用户不需要每天去管理目标；它的价值体现在 Capture 自动归类。

## 必须保留的约束（视觉可改，逻辑不可改）

`todayCommand` 为权威 · actual 与 predicted 分开显示，缺失就是缺失 · 示例与个人数据严格隔离 · 不出现 Life Score · 关联≠因果 · 不用全局天数门槛锁住工作区 · 保存只在 ACK 后显示成功 · 不同动作不混基线、不同单位不混量纲。
