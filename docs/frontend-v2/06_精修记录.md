## 首用「怎么开始」——现状与诚实说明

- 新路径：欢迎（价值一句话）→ 3 个点选题（睡眠 / 整体状态 / 今天想推进什么）→ 今天的第一个建议 → 进入 Today。选「我想先建一个目标」仍走原来的 领域→表单→预览 路径，**没删**。
- 点击数：欢迎 1 + 答题 3 + 看建议 1 + 进入 1 = **6 次点击，0 次打字，不需要任何历史数据**。旧流程也是 6 次交互（含 1 次打字），但结束时 Today 是空的、没有任何建议。所以**点击数没有变少，变的是：第 5 次点击就拿到第一个建议，进入 Today 时已有个人内容**。
- 建议是**规则表**（`firstStart.ts`，有单测），不是 AI；界面标「通用建议」，并写明「还没有你的历史数据，不是你的个人规律」。
- 写入：1 条 `StateCheckIn`（较差/一般/不错 → 2/3/4）+ 1 条睡眠自评 `ContextLog`（单位固定为「睡眠自评1-3」，**不与真实睡眠分钟混用**）。写入后等待持久化 ACK 才进入 Today；失败留在原页并提供「重试」，重试**不会重复创建**。
- 健康 / 日历不在首用里要权限：只有一行「之后在设置里再接」。
- **未验证**：第 3 / 7 / 21 天各看到什么。S0–S3 的门槛在代码里（见上），但我没有逐日跑过这个新入口；`docs` 里不写没验证过的行为。
- **未验证**：真机 iOS。`OnboardingScreen` 在原生与 Web 共用，新增屏用的是 RN 基础组件，但键盘与安全区**没有在真机上看过**。

1. **Today 标题「先用保守启动，顺便补一条状态或睡眠信号。」**：这是产品文案/判断逻辑输出，不属于视觉精修；它是屏上最大的字却最泛，值得你单独决定。

## 第二轮的实现细节与边界（如实说明）

- **R5 的作用范围**：首用答案存在 `AsyncStorage['questlife.firstStart.v1']`（只存三个答案和日期，不是新的业务数据）。Today 仅在「答案日期 = 今天 且 今天还没有执行记录」时显示首用建议；有第一条执行记录后自动让位给 `todayCommand`。第二天不再显示。
- **R5 唯一的行为改动**：显示首用建议时，若 `todayCommand.primaryAction === 'create_goal'`，点主卡打开 Capture，而不是建目标表单——因为卡上写的是「先做 2 分钟」，点进去却要求建目标会自相矛盾。其他情况主卡行为不变。
- **R4 中途发现的回归，已修**：第一版把聚焦边框改成 1px，导致输入框自动增高的测量每次多出 2px，打字后一路长到 156px 上限。改为保持 2px 边框盒、边框透明、用内阴影画 1px 描边后，打字后高度回到 68px（脚本测量）。
- **首用页面顺带修了**：「‹ ‹ 返回」双箭头；欢迎页正文的孤字（`textWrap: pretty`）。
- **原生**：玻璃卡片与光晕的 CSS 只在 Web 生效；原生回落为主题 surface 色（`V11GlowOrb` 用 react-native-svg，跨平台）。**原生未验证**。
- 建议页内容较少，居中偏上后上方仍有约 1/6 屏留白；没有为填满而加内容。
