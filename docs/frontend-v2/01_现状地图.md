## 2. 数据来源与状态

- **单一 Store**：`src/store.tsx`，一个 React Context，`useStore()` 返回整个 `data`（`AppData`）+ 约 80 个动作。数据读写 AsyncStorage（Web 下 = `localStorage['questlife.v1']`）。
- **没有 selector**：任何组件调用 `useStore()`，都会在**任何一处数据变化**时重渲染（confirmed：`createContext` + 一个整体 value，`useStore` 仅 `useContext`）。
- **持久化 ACK 已有**：`waitForLocalWrites()` / `waitForExecutionLog(id)` / `localPersistence {pending, failed}` / `retryLocalWrites()`；失败时 `LocalPersistenceNotice` 显示"保存失败 + 重试"。**这条链路是好的，v2 必须沿用。**
- **`todayCommand`**（`src/utils/todayCommand.ts`）：纯函数 `buildTodayCommand`，优先级固定：待完成的 capture → 低状态（≤2）→ 刚记录的反馈 → 当前/下一个日程 → 进行中的计时 → 未记录的技能 → 空状态（建目标）→ 兜底"记一句话"。**它是 Today 的数据权威。**
- **Capture 流水线**：`addRawCapture(text)`（原文先落盘）→ `/api/parse`（`authenticatedAiPost`，需登录与云端 AI 开启）→ `updateRawCapture({parsed.entries})` → `HomeCapturePending`（2727 行）逐条确认 → `createExecutionLog` → `waitForExecutionLog` ACK。解析失败原文仍保留。
- **云端 AI 默认关闭**（`src/services/aiPreferences.ts`：`enabled:false`；设置页原文"默认关闭……请先在上方登录并连接本机记录，再开启云端 AI"）。**这意味着：新用户默认没有 AI 解析。**
- **已有"快捷记录"引擎**：`QuickCaptureSuggestionEngineV1`（`src/platform/quickCapture.ts`），按"此刻日程/重复/同时段/目标/最近"给出 ≤3 个建议，Capture 面板里的"最近记录"chip 即来自它。
- **数据来源标注**：`DataRecordOrigin` 含 `OWNER_OBSERVED / OWNER_CONFIRMED_AI_PARSE / PASSIVE_IMPORTED / SYNTHETIC / QA_TEST / DEBUG_FIXTURE / DERIVED / LEGACY_UNKNOWN`；示例数据可用 `SYNTHETIC` 标记。

## 3. 用户真实走一遍

**首次打开 → 第一次记录 → 第一次看到结论**（Playwright 脚本化，dev 服务；`01–07`、`10–13` 号截图）：

| 步骤 | 点击 | 看到什么 | 卡在哪 |
|---|---|---|---|
| 1 选语言 | 1 | "选择你的语言" | 没有一句话讲清 App 有什么用 |
| 2 定位页 | 1 | "把目标变成每天能执行的系统"+3 条要点 | 讲的是功能列表，不是价值 |
| 3 选领域 | 1 | 8 个领域 | 用户要先回答"我想解决什么"才能继续 |
| 4 填目标 | 打字 1 次 + 可选 4 项 | 名称、当前水平、目标、每周频率、单次时长 | **表单**，且全是"未来"信息 |
| 5 预览 | 1 | "系统将创建：1 目标 / 4 模块 / 6 技能" | 概念：模块、技能 |
| 6 确认 | 1 | 进入 Today | |
| 合计 | **6 次交互**（含 1 次打字），脚本化墙钟约 6.6 秒 | Today：通用文案 + "未记录" + "还没有记录" | **没有任何个人价值，也没说下一步** |

**第一次记录（Today → 记录条 → 输入 → 发送）**：
- 点"记录"条（1）→ 面板弹出（约 1 秒含动画）→ 输入（打字）→ 点右侧小箭头（2）→（有云端 AI）等待 `/api/parse` → 候选确认卡 → 确认保存。**最少 3 次点击 + 一次打字 + 一次网络等待。**
- 云端 AI 默认关闭 → 新用户的"发送"会走本地兜底或失败重试路径。这条路径我**没有在本地走通**（无后端/账号），**未验证**。
- 键盘：Capture 面板在 390×844 下，输入框偏小，"最近记录"chip 很小（`12_capture-open.png`）；发送按钮是 44×44 灰色小箭头，**未激活时与背景几乎同色**。

**第一次看到结论**：首用后 Today 的"结论"是模板文字；真正的洞察在"洞察"页，但需要多日数据，且界面是行情终端风格（`22_insights.png`），非专业用户读不懂。

## 4. 输入路径（现在 vs 目标）

| 指标 | 现在 | 目标（本次） |
|---|---|---|
| 打开 → 开始输入 | 1 次点击（点记录条）+ 约 1 秒弹出 | 0 次（输入框常驻在首屏） |
| 记一条的最少点击 | ≥3 + 打字 | ≤2（输入框内回车/发送 + 一次确认） |
| 单手 | 记录条在屏幕上部（顶部 ~200px 处）；拇指区只有 Tab 栏 | 输入与确认都在拇指区 |
| 失败状态 | 解析失败卡片 + 重试（有）；离线/未开 AI：**无明确引导** | 三种失败各有明确界面 |

## 5. 原生 iOS 为什么"用不了"（只写有依据的；全部**未在真机验证**）

1. **安装版本落后于源码，且签名已过期（最强证据）**。`V1_COMPLETION_LEDGER.md`：物理 iPhone 13 Pro 上安装的是 `8f23b19`，"Physical iPhone still runs `8f23b19`, not this newer source"；之后的 UIScene 修复（`fe6b163`）和 Capture 输入框高度修复（`a0c0e8e`）**只在模拟器验证过，从未装到手机**。同一份文档写明免费 Personal Team 描述文件"**expires 2026-10-21 17:15:52 UTC**"，今天是 2026-10-27——**手机上这个 App 很可能已经打不开**（启动即被 iOS 拒绝）。推断强，仍需用户在手机上确认。
2. **Capture 输入在键盘下被裁切**：台账记录"Simulator Capture showed a clipped input top/first line with the keyboard"，修复"post-fix visual/keyboard verification remains UNVERIFIED"。
3. **Today 全 Store 订阅**：`HomeScreen` 解构 `useStore()` 的整个 `data`，并持有约 100 个 `useState`；任何记录写入都会让整个 4165 行组件重渲染（confirmed 于代码）。`wip/today-perf` 的 `7b10a17` 已减少重复计算，但订阅模型没变。
4. **UI 被业主判定不合格**：台账："Owner reports the UI is inadequate; visual/product acceptance remains NOT PASSED"。
5. 其他"可能"项（未找到足够代码证据，故只列出、不下结论）：Sheet 在原生走不透明降级、洞察图表 WebView 初始化、长列表非虚拟化。代码里确实存在 `react-native-webview` 依赖与 `*.native.tsx` 的独立 Sheet 实现，但我没有找到能证明它们导致卡顿的依据。
