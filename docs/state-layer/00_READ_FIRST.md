## 做了什么
- **识别**：5 类加「说不准」，13 条透明规则（纯函数，157 项单测，1200 种输入组合全覆盖）。
  - 阈值相对你本人的中位数；不足 7 次时用量表中点，并写明「还没有你的基线」。
  - 信号冲突或缺失时输出「说不准」，不硬分类。
- **解释**：一行理由，加上「没用到」的信号。三种依据样式不同，一眼可分：「规则判断」描边、「通用依据」浅底、「你的记录」深底。可以一键改正，改正会保存。
- **行动**：每类一个首选、一个备选，加「重排今天」。
  - 「清空脑子」：现在做 / 排时间 / 放下，排时间必须写具体时间。
  - 任何日程改动都是：预览 → 你点确认 → 应用 → 可撤销。**没有自动改日程。**
- **回访与学习**：选了动作 20 分钟后，Today 上出现回访卡，2 次点按。
  - 按（类型 × 动作）计数；不足 5 次只显示次数。
  - 抛硬币模式在设置里，默认关。
- **周期**：洞察里新增「状态」标签页。
  - 30 / 90 天日历，没签到的天是空格。
  - 滞后一天的睡眠描述，满 10 组才显示。
  - **不预测。**
- **todayCommand 仍是权威**：签到写入的精力会让 todayCommand 自己给出「2 分钟最低动作」；状态卡永远在它旁边，不替换它。
- **PWA**：manifest、iOS 主屏幕标签、离线外壳、离线提示。本地生产构建实测：断网刷新后能看到 Today 和数据。**没有部署。**
- **后端缺口：无。** 新字段放在现有实体的 payload 里，单测证实同步和备份校验都原样接受。

## 需要你拍板（≤5，每条附推荐）
1. **合并规则**：状态卡在 Today 最上方，todayCommand 的动作仍是最大字号，但会被推到第一屏下方。
   - 推荐：先这样用一周；如果你总是只看状态卡，再考虑把 todayCommand 移到状态卡里面（这要改 Today 结构，我没做）。
2. **iOS 状态栏样式**：现在是 `default`，不会出错，但深色主题下状态栏是白的。
   - 推荐：真机确认安全区后改成 `black-translucent`。
3. **PWA 图标**：现在用的是现有的占位风格图标。
   - 推荐：换成正式图标后再加到主屏幕。
4. **部署 PWA 到哪里**：推荐 Vercel 的一个**预览**环境（不碰旧的 Owner Production）。步骤见交接文档，**等你确认后再做**。
5. **抛硬币模式**：默认关。
   - 推荐：用一两周、规则稳定后再打开，并且只在「过载：清空脑子 vs 快走」这种两个都合理的场景使用。

EXPO_NO_TELEMETRY=1 npx expo start --web --port 8101      # 不要加 CI=1
