## 决定

| # | 决定 | 理由 | 备选 | 可逆 |
|---|---|---|---|---|
| 1 | 新字段全部放进 `StateCheckIn.stateLayer` 子对象；`ScheduleBlock.demand` 和 `ContextLog.brainDump` 都是可选字段 | SyncV2 对这几类实体的校验是 `.passthrough()`（`registry.ts:47/66`），单测证实同步和备份校验都原样接受 → **不需要 migration，没有后端缺口** | 新实体类型（要改同步合约和后端） | 是 |
| 2 | 精力 → `energy`，紧绷 → `stress` + `stateLayer.tension`，`overall = energy` | `overall` 是同步必填项；用精力做代理，现有读取方（Today 状态行、todayCommand、洞察）继续工作。`overallFrom: 'energy'` 记下了来源，以后可以剔除 | 再问一题「整体」（多 1 次点按） | 是 |
| 3 | 基线只用状态层签到，不用旧签到 | 旧签到的 `stress` 默认值是 3（用户没动也会写入），会污染紧绷基线 | 全部签到 | 是 |
| 4 | 规则加了「精力居中」的 #11–#13，「挂着很多事」要求紧绷不低才判过载 | 原设计没覆盖精力居中；很松但事多更像「事多不急」，硬判过载会误导 | 按原表 | 是 |
| 5 | **合并规则**：todayCommand 永远是 Today 的主动作（24px 最大字号）。状态卡在它上方，卡内首选动作 19px | 任务要求状态层「只能作为输入或在旁边显示」 | 状态卡替换 Today 主动作（违反权威） | 是 |
| 5a | 状态层**作为输入**：签到写入 `energy`，todayCommand 的 `isLowState` 据此给出「2 分钟最低动作」 | 这是现有路径，不需要改 todayCommand | 改 todayCommand 读 stateLayer（越界） | — |
| 5b | **冲突时收起**：todayCommand 在处理待完成的记录、反馈复看，或有进行中的计时时，状态卡只显示类型和理由，并提示「先完成上面这件事」 | 这些是必须先做完的事务，状态建议可以等 | 一直显示 | 是 |
| 5c | 有状态层签到后，首用的「通用建议」让位给 todayCommand | 首用建议是「还没有任何个人信息」时的默认值；用户明确签到后，再显示它会出现两套说法 | 首用建议一直保留到第一条执行记录 | 是 |
| 6 | 签到直接放在卡片里，没有单独的 Sheet | 任务要求「≤3 次点按」，打开 Sheet 本身就多一次点按。现在 2 次点按完成；选填项默认折叠在「补充两项（可选）」里 | 签到 Sheet | 是 |
| 7 | 所有写入都等持久化 ACK 才显示结果；失败时显示「重试」，重试走 `retryLocalWrites`，**不重复创建** | 产品逻辑硬要求 | — | — |
| 8 | 「重排今天」和「清空脑子」的排时间都走：预览 → 用户点确认 → owner DecisionEpisode（PROPOSED → ACCEPTED → APPLIED）→ `applyDecisionSchedulePatch` → 可撤销 | 任务硬要求「不允许自动改日程」；复用 planPatch 的冲突检测和撤销保护（已开始或已有执行记录的块不能撤销） | 直接写 scheduleBlocks | 是 |
| 9 | 重排算法：新顺序里第 i 个块不早于原来第 i 个块的开始时间 | 保留用户自己留的空隙；顺序本来就对时返回「不用动」，不会无意义地挪时间 | 紧密排布（会压掉所有空隙） | 是 |
| 10 | 「清空脑子」用本地确定性切分，不调用 AI | `/api/parse` 要登录，云端 AI 默认关（与首用决策 #11 同理） | 调 /api/parse | 是 |
| 11 | 回访存为一条新的 StateCheckIn（`kind: 'follow_up'`, `followUpOf`） | 回访本身就是一次状态测量，也会更新 Today 的状态 | 存进 DecisionEpisode.followUpOutcomes（需要为每次签到建 episode，太重） | 是 |
| 12 | 只在有实测睡眠分钟时才说「不是没睡够」 | 实测发现：仅凭首用的睡眠自评「一般」就说了这句话，属于过度推断 | — | — |
| 13 | 用户改正后，理由行标「规则原判」，下面一句写「你改成了…，统计按你的改正」 | 实测发现：改正后标题是「燃料不足」，理由行却写「更像过载」，自相矛盾 | 重新生成理由（会掩盖规则判断） | 是 |
| 14 | `?state_layer=0` 在 Web 上隐藏整个状态层（Today 卡、洞察标签、设置开关） | 回退开关，也用来拍同数据的改前 / 改后对照 | 不加开关 | 是 |

## 实测中发现并修掉的问题

- 重排一开始是紧密排布，会把用户留的空隙全压掉。已改为保留原始开始位（#9）。
- 「清空脑子」完成后，「撤销」藏在卡片底部视野外。已移到动作区下方。
- 卡片里的通用依据和「没用到」两行太长，挤成三行小字。已压缩成「还没有你的基线（0/7 次）」和「没用到（没有数据）：…」。
- 首用建议和状态签到同时出现，说法不一致。已修（#5c）。
- 「不是没睡够」的过度推断（#12）。
- 改正后理由行和标题自相矛盾（#13）。
- Thayer 1987 原来写成「随机对照」，实际是 18 人的组内比较，已改正文案。
