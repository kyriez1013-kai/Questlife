# 02 状态模型 v0

> 规则是**起点假设**，不是结论。需要用用户本人至少 30 天的数据校准。全部是透明规则（纯函数），没有模型、没有 AI。
> 代码：`src/state-layer/`。单测：`npm run test:state-layer`。

## B1. 输入

| 输入 | 必填 | 取值 | 存哪 | 备注 |
|---|---|---|---|---|
| 精力 | ✅ | 1–5（没电…很足） | `StateCheckIn.energy` | 同时写 `overall = energy`（见下） |
| 紧绷 | ✅ | 1–5（很松…很紧） | `StateCheckIn.stress` + `stateLayer.tension` | 方向与现有「压力」一致 |
| 脑子里挂着的事 | 选填 | none / few / many | `stateLayer.openLoops` | 跳过 = 缺失，不补默认值 |
| 对眼前这件事 | 选填 | want_cant / can_dont_want / unsure | `stateLayer.pull` | 同上 |
| 最近两晚睡眠 | 被动 | 分钟 | 不新增存储 | 来源优先级：同步来的 HealthKit 睡眠 → `ContextLog(sleep, min)`；首用的「睡眠自评1-3」只作弱信号，不与分钟混用 |
| 静息心率 / HRV | 被动 | bpm / ms | 不新增存储 | 只用同步来的观测值；Web 本地没有就跳过，并写进「没用到」 |
| 昨天训练分钟 | 被动 | 分钟 | 不新增存储 | `ExecutionLog.taskType ∈ {strength_training, cardio_recovery}`，0 视为未记录 |
| 今天日程占用 | 被动 | 小时 | 不新增存储 | 今天剩余 `scheduleBlocks`；Web 没有外部日历 |
| 当前时段 | 被动 | morning…night | `StateCheckIn.timeBlock` | 现有字段 |

**新增字段全部在 `StateCheckIn.stateLayer` 一个子对象里**（`v: 'questlife.state-layer.v0'`）。SyncV2 对 stateCheckIns 是 passthrough 校验，可以原样同步；不加表、不加 migration。旧数据没有这个子对象，照常读取。

**`overall = energy` 的理由（改进点，写明）**：`overall` 是同步 schema 的必填项。两次点按的签到不问「整体」，用精力作代理：
- 现有读取 `overall` 的地方（Today 状态行、`todayCommand.isLowState`、洞察）继续工作；
- 低精力会让 todayCommand 给出「2 分钟最低动作」，这正是**状态层作为 todayCommand 输入**的路径。

`stateLayer.overallFrom = 'energy'` 记录了这一点，以后分析时可以剔除。`focus` / `mood` 不问就不写（缺失就是缺失）。

## B2. 状态识别

### 基线（相对用户本人）
- 只用**状态层签到**（`stateLayer.kind = 'check_in'`）建基线，排除当前这次。旧签到的 `stress` 默认值是 3，不可信，所以不纳入。
- **≥ 7 次**：中位数 `m` 与尺度 `s = max(1.4826 × MAD, 1)`。
  - 尺度下限 1：量表是整数，半档没有意义。
  - 偏高：`x ≥ m + s` 或 `x = 5`。偏低：`x ≤ m − s` 或 `x = 1`。端点永远算偏高/偏低。
- **< 7 次**：退回量表中点（`m = 3, s = 1`），界面写明「还没有你的基线（已有 n 次，满 7 次后按你的常态判断）」。
- 睡眠：
  - ≥ 7 晚时，「偏少」= 近两晚均值 ≤ 个人中位数 − `max(1.4826×MAD, 30 分钟)`。
  - 不足 7 晚时，用通用阈值 6 小时，并标「通用依据」。
- 静息心率 / HRV：只在 ≥ 7 个观测时用个人基线（偏高 = ≥ 中位数 + max(尺度, 3 bpm)；HRV 偏低 = ≤ 中位数 − max(尺度, 5 ms)）。没有个人基线就不用——个体差异太大，没有可靠的通用阈值。
- 昨天训练：「偏多」= ≥ max(60 分钟, 个人训练日 75 分位)。不足 7 个训练日时只用 60 分钟，标「通用依据」。

**身体账户** = 偏低（任一身体信号偏低）/ 正常（至少一个身体信号可用且都不偏低）/ 未知（一个都没有）。

### 5 种类型 + 说不准（按顺序匹配，命中即止）

| # | 规则 | 结果 | 规则 id |
|---|---|---|---|
| 1 | 精力低 且 紧绷高 | 过载 | `overload.low_e_high_t` |
| 2 | 挂着的事 = 很多 且 紧绷不低 | 过载 | `overload.many_loops` |
| 3 | 精力低 且 身体账户偏低 | 燃料不足 | `low_fuel.body_low` |
| 4 | 精力低 且 身体账户正常 且 选了「想做但做不动」 | **说不准**（信号冲突） | `unclear.conflict_pull_body` |
| 5 | 精力低 且 身体账户正常 | 低唤醒 / 回避 | `low_arousal.body_ok` |
| 6 | 精力低 且 身体账户未知：选「做得动但不想做」→ 低唤醒；选「想做但做不动」→ 燃料不足；都没选 → **说不准**（缺失） | — | `low_arousal.pull` / `low_fuel.pull` / `unclear.missing_body` |
| 7 | 精力不高 且 选了「做得动但不想做」 | 低唤醒 / 回避 | `low_arousal.pull_mid` |
| 8 | 精力高 且 紧绷高 | 紧绷有劲 | `tense_energy` |
| 9 | 精力高 且 紧绷低 | 平静有劲 | `calm_energy` |
| 10 | 精力高 且 紧绷居中：紧绷 > 你的中位数 → 紧绷有劲；否则 → 平静有劲 | — | `tense_energy.mid` / `calm_energy.mid` |
| 11 | 精力居中 且 紧绷高：挂着的事 = 一两件 → 过载；= 没有 → 紧绷有劲；没填 → **说不准** | — | `overload.mid_e` / `tense_energy.mid_e` / `unclear.mid_e_high_t` |
| 12 | 精力居中 且 身体账户偏低 | 燃料不足 | `low_fuel.mid_e_body_low` |
| 13 | 其余（精力居中、紧绷不高、没有别的信号） | **说不准**：都在你的常态范围内 | `unclear.in_range` |

「说不准」不硬分类，给最省力的下一步：「先做 Today 上那一步，10 分钟后再看」。

**改进点（相对原设计）**：
- 精力**居中**的情况原设计没有覆盖，我加了 #11–#13。
- 「过载」的「挂着的事很多」要求紧绷不低（#2）。原因：一个人很松但挂着很多事，更像「事多但不急」，硬判过载会误导。
- 冲突（#4）与缺失（#6 第三种、#11 第三种）明确输出「说不准」。

### 用户改正
理由行旁有「不是这样」，可以选另一种类型。改正存在 `stateLayer.correction = { type, at }`，原分类保留。之后所有汇总都用**改正后的类型**；规则命中和改正的对照留作校准数据。

## B3. 解释

每次识别产出：
- **一行理由**：用到的信号 + 结论。例：「精力 2、紧绷 4，挂着很多事；近两晚平均 7.2 小时，在你的常态范围内 → 更像过载，不是没睡够。」
- **没用到的信号**：例：「没用到：心率（没有数据）、睡眠（没有记录）」。
- **三种依据标签**（界面上用不同样式，一眼可分）：
  - 「规则判断」：分类本身，附规则 id。
  - 「通用依据」：动作背后的研究，一句话加出处（见 `03_科学依据.md`）。
  - 「你的记录」：（类型 × 动作）的回访计数。少于 5 次只显示次数。

## B4. 行动

| 类型 | 首选 | 备选 | 通用依据 |
|---|---|---|---|
| 平静有劲 | 把今天最难的事提前到现在（→ 重排预览） | 保护这段时间：25 分钟不切换 | 任务难度匹配精力窗口（规则判断） |
| 紧绷有劲 | 做清单式任务，重大决定推迟 | 先 10 分钟快走 | Thayer 1987/1989 |
| 燃料不足 | 降级任务，安排恢复或早睡（→ 重排预览） | 休息 20 分钟以内 | 身体账户优先（规则判断）；Loy 2013 关于低强度运动的限制 |
| 过载 | 清空脑子 | 10 分钟快走 | Masicampo & Baumeister 2011；Thayer 1987 |
| 低唤醒 / 回避 | 5 分钟试探：只做 5 分钟，到点再决定 | 换环境，或换一件更想做的事 | Kurzban 2013；Marcora 2009 |
| 说不准 | 先做 Today 上那一步，10 分钟后再看 | 再签一次 | — |

### 重排今天
- `demand`（深度 / 浅 / 体力 / 恢复 / 社交）是 `ScheduleBlock` 的可选字段。没有时按 `taskType` 推断：
  - deep_study、creative_building → 深度；
  - light_review、admin、life_maintenance → 浅；
  - strength_training → 体力；
  - cardio_recovery → 恢复。

  推断值在预览里标「推断」，用户点一下可以改，改动作为 planPatch 的一部分写入、可撤销。
- 每种类型的优先顺序：
  - 平静有劲：深度 → 体力 → 浅 → 社交 → 恢复
  - 紧绷有劲：浅 → 体力 → 社交 → 恢复 → 深度
  - 燃料不足：恢复 → 浅 → 社交 → 体力 → 深度
  - 过载：浅 → 恢复 → 体力 → 社交 → 深度
  - 低唤醒：体力 → 浅 → 社交 → 深度 → 恢复
- 算法：
  1. 只动今天、还没开始、非 `fixed`、未 `placementLocked` 的块。
  2. 窗口 = [现在（取整到 5 分钟）, 这些块原来最晚的结束时间]。窗口内的固定块当障碍。
  3. 按优先顺序依次放到最早能放下的位置，同优先级保持原顺序。原块之间的空隙会被压缩，所以「改动多少」在预览里逐条显示。
  4. 放不进窗口时延长到 23:59；再放不下就**不重排**，告诉用户「今天排不开」。
  5. 结果交给 `createDecisionPlanPatch`，预检 `applyDecisionPlanPatch` 不冲突才显示预览。
- 链路：
  1. 预览：逐条 before → after。
  2. 用户点「确认重排」。
  3. 生成一条 owner DecisionEpisode：PROPOSED → ACCEPTED → APPLIED。
  4. `applyDecisionSchedulePatch`。
  5. 保存后显示「已重排 · 撤销」。撤销走 `undoAppliedDecision`（含「已开始 / 已有执行记录不可撤销」的保护），再 `undoDecisionSchedulePatch`。
  6. **没有任何自动应用。**

### 清空脑子
1. 输入框，一条一行（也接受「，」「；」「、」分隔）。本地确定性切分，不调用 AI。
2. 每条三选一：现在做 / 排时间 / 放下。「排时间」必须给具体时间：推荐今天最近的 3 个空档，或自己输入 HH:MM，默认 30 分钟。
3. 完成后：
   - 写一条 `ContextLog{type:'custom', label:'清空脑子', value:条数, unit:'件', brainDump:{items}}`，ACK 后才显示成功。
   - 「排时间」的条目作为 planPatch 的 add 操作，走同样的预览 → 确认 → apply → 撤销。

## B5. 回访与学习

- 用户点了首选或备选，就在签到上记 `stateLayer.choice = { actionId, slot, randomized, at }`。
- 回访在 `at + 20 分钟` 后到期，当天有效。到期后 Today 上出现非侵入卡片：「刚才〈动作〉之后，现在怎么样？」，同样两个 1–5 控件，2 次点按完成；可选「下一件事做了吗」；可忽略。
- 回访存为一条新的 StateCheckIn：`stateLayer.kind = 'follow_up'`、`followUpOf = 原签到 id`，同样经过分类，所以 Today 状态随之更新。忽略记 `choice.followUpDismissedAt`。
- 汇总（`summarizeOutcomes`）按（改正后的类型 × 动作）计数：精力上升 / 持平 / 下降，紧绷下降 / 持平 / 上升，下一件事做了 / 没做 / 未答。
  - **n < 5**：只显示「做过 3 次」。
  - **n ≥ 5**：「对你来说：做过 6 次，其中 4 次精力回升、3 次紧绷下降」。只给计数，**不给百分比，不说因果**。
- **抛硬币**（默认关，设置里可开）：类型的首选和备选都合理时，签到后显示「随机选一个」，记 `randomized: true`。汇总里随机分配的次数单独显示，这是单人微随机试验最干净的数据。

## B6. 周期视图（只描述，不预测）

- 状态日历：最近 30 / 90 天，每天取当天签到的主要类型（众数，平局取最新），**没签到的天是空格**。
- 汇总：「过去 30 天：过载 9 天、低唤醒 6 天…，记录了 22 天」。
- 滞后一天的描述：「睡眠低于常态的次日」vs「其余次日」中燃料不足的天数，只给计数。**至少 10 组（前一晚睡眠已知、次日有分类）才显示。**
- **不做任何预测提醒**。个体层面的早期预警信号灵敏度低，见 `03_科学依据.md`。
