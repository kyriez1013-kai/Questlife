QuestLife 五个快捷指令

适用候选站点：https://questlife-v1-release.vercel.app/ 。先在同账号「个人」登录并生成个人令牌。此文件不包含令牌；不要把令牌放在 URL、截图、聊天或共享快捷指令里。

服务启用条件与连接说明

首次连接

本轮没有执行线上 migration。由用户在候选 Supabase gttcoocfkqwvsqfwxpyo 的 SQL Editor 审阅并执行 supabase/migrations/202611050001_shortcut_inbox.sql，不是旧 Owner 项目。它依赖已存在的 SyncV2 migration；以事务执行，结构不符会全部中止。之后回到「个人 → 手表与快捷指令 → 生成个人令牌」。令牌只显示一次；重新生成立即使旧令牌失效，五个快捷指令需要一起更新。撤销不删除原有记录。

所有请求发到 https://questlife-v1-release.vercel.app/api/inbox，方法 POST，JSON 请求体。请求头 Authorization 的值为 Bearer 加个人令牌（空格必需）；另加 Content-Type: application/json。这是只写权限，不能用它读取账号。上限每分钟 30 次、每天 1000 次，每次最多 100 个样本/事件、128 KiB，不调用 AI；Capture 在 App 内确认前不算执行记录。

发送动作的公共设置

在 iPhone「快捷指令 → + → 添加操作」建立下列操作。iOS 的本地化名称可能略有区别，用搜索框搜括号内英文名称。

1. 添加「生成 UUID」（Generate UUID），设变量 requestId。每个新批次生成一次；网络失败重试同一请求时保留原 UUID 和完整请求体，不重新抽取数据。

2. 添加「当前日期」，再「格式化日期」，自定 yyyy-MM-dd'T'HH:mm:ssXXX，设 at。不要用没有时区的文本。

3. 对同一个日期再格式化为 Z，例如 +1100。用「匹配文本」分出符号、前两位小时、后两位分钟，用「计算」得到带符号的分钟数：11*60+0=660；负号则乘 -1。保存数字 timezoneOffset。不要固定写 660，夏令时和旅行会改变它。

4. 添加「字典」（Dictionary），按下方各快捷指令填字段；数字选 Number，列表选 Array，嵌套字段选 Dictionary，不把整个 JSON 拼成未转义文本。

5. 添加「获取 URL 内容」（Get Contents of URL），展开选项，POST / Headers 如上，Request Body 选 JSON，使用字典字段。添加「获取字典值」读取返回的 ok。只有 true 才显示「已接收」通知。

6. 返回 401：更新令牌；403：在个人页同意健康同步；409：刷新 App 后重试回访；429：稍后重试，保留同一请求；503 或网络失败：不要显示保存成功。App 的账号同步后才能看到服务器收到的数据。

01 · 记录状态

1. 重命名快捷指令为 QL记录状态。

2. 添加「从菜单中选取」：标题「现在精力？」；五项「1 没电、2 偏低、3 一般、4 有劲、5 很足」。每个分支放对应的「数字」，菜单结果设为 energy。

3. 再添加「从菜单中选取」：标题「现在紧绷？」；五项「1 很松、2 较松、3 一般、4 较紧、5 很紧」，结果设数字 tension。

4. 添加公共部分，字典字段：kind 文本 state；requestId、at、timezoneOffset；energy 和 tension 用上面的数字变量。

5. 快捷指令详情中开启「在 Apple Watch 上显示」。在手表「快捷指令」中运行，或编辑支持快捷指令复杂功能的表盘，选择 QL记录状态。首次网络/运行权限在设备上确认。

6. 回到 App、同账号完成同步；Today 状态条显示该状态记录。来源存为 watch_shortcut，不会凭空附带 Health 数据。

02 · 清空脑子

1. 新建并命名 QL清空，添加「听写文本」（Dictate Text），语言按实际使用选择，停止听写选择停顿后。

2. 公共部分字典：kind: capture；requestId、at、timezoneOffset；text 取听写结果。空文本不发送。

3. 收到确认后，在 App 的 Capture 待确认入口继续解析、修改和确认。API 不替你推断时长，不自动创建 ExecutionLog，也不绕过现有 AI 预算或确认。

4. 可开启「在 Apple Watch 上显示」。听写可用性、联网和权限必须在真机验证。

03 · 回访提醒

1. 新建 QL回访提醒，接收快捷指令输入类型「文本」。不需要个人令牌，也不发 API。

2. 添加「当前日期 → 调整日期」，加 25 分钟。

3. 添加「添加新提醒事项」，标题「QuestLife：现在精力怎么样？」；提醒日期用调整后的日期；备注/URL 填「快捷指令输入」。选择你同步到手表的提醒事项列表。

4. App 选择调节动作后，点「25 分钟后提醒」会通过 shortcuts://run-shortcut?name=QL回访提醒&input=text&text=... 传入包含当前状态记录 ID 的回访链接。

5. 提醒到达后打开链接，在 App 五档选精力；保存到该状态记录的 choice.energyFollowUp。未传链接时不要造默认状态记录 ID，应停止并提示从 App 发起。提醒是否出现在表盘由系统通知设置决定。

04 · 健康同步

先在 App「个人 → Apple 健康 → 同意云同步」明确开启。关闭后新写入会拒绝；删除按钮只删除 shortcut 来源，不影响 HealthKit 原件或其他来源。

1. 新建 QL健康同步；「当前日期 → 调整日期」减 2 天。

2. 添加「查找健康样本」（Find Health Samples），开始日期在两天前至现在。四种类型分四个批次处理：睡眠分析、步数、静息心率、心率变异性 SDNN。首次在系统授权页只授权你愿意提供的类型。

3. 先选择一个明确来源设备/App（例如 Apple Watch），不混加手机和手表累计步数。睡眠只选「睡眠/核心/深度/REM」实际睡眠区段，排除「卧床」和「清醒」；不要把类别枚举数字当分钟。

4. 「重复每一项」，用「获取健康样本详细信息」读取开始/结束日期、来源、数值。日期均格式化为上面的 ISO 格式。睡眠数值用开始到结束的「获取日期之间的时间」分钟；步数 count，静息心率 bpm，HRV ms。无法读取来源/必要时间的样本不发送，不补默认值。

5. 每个样本的字典字段：metric（sleep / steps / resting_heart_rate / hrv）、value 数字、unit（min / count / bpm / ms）、startAt、endAt、source。HRV 额外填 measurementMethod: sdnn，不可把未知算法冒称 SDNN。

6. 把每个字典「添加到变量」samples；每满 100 条发送一批，再清空该批变量。最后不足 100 条也发送；0 条跳过并显示「未读取到样本」，不上传 0。每批一个新 requestId。

7. 请求字典：kind: health，公共三字段，samples 数组。多个批次请间隔至少 3 秒，低于限流；日常同步最近 2 天可重叠，服务端按类型、算法、起止与来源去重。

8. 快捷指令 → 自动化 → + → 特定时间，08:00，每天，选择「立即运行」（旧版为关闭运行前询问），运行 QL健康同步；再建立 21:00 自动化。健康隐私和锁屏条件可能阻止后台执行；首次手动运行确认，不能把自动化已创建当作已同步。

9. 返回个人页查看最近同步时间。数据先到候选 SyncV2，再由同账号 App 拉取至现有 DeviceRepository。睡眠重叠使用现有区间并集，不等于已证明完整一夜；HRV 算法不混合。

05 · 日历同步

1. 新建 QL日历同步。「查找日历日程」（Find Calendar Events）：范围今天，从当天开始到次日开始，包含跨越当天的日程，选择你同意提供的日历。不要只取开始时间在今天的事件，以免漏掉跨夜占用。

2. 「重复每一项 → 获取日历日程详细信息」读取标题、开始、结束、日历名称和全天标记。如果系统提供事件标识符，用它作为 id；没有标识符时用日历名 + 标题 + 开始日期组成稳定文本（仅缓存标识，不冒称系统事件 ID）。

3. 每项字典：id、calendarId（可用日历名称作稳定缓存键）、title、startAt、endAt、allDay 布尔值。日期必须带时区，保留真实持续时长。仅同步 busy 占用；能读到空闲标记的事件排除。

4. 请求字典：kind: calendar；公共三字段；date 用当前日期自定 yyyy-MM-dd；events 数组。无日程时也发送空数组，表示这次主动同步的当天缓存为空。

5. 每天必须一次发送完整当天缓存，不分批覆盖；超过 100 个事件时停止并提示，不截断后假称完整。App 只显示/避让此只读缓存，不写系统日历，也不变成用户日程块。

6. 在系统日历新建/移动/删除之后再次运行。调整建议只知道最近缓存，不保证系统日历实时状态。关闭权限不能解释为无冲突，无法读日历时停止发送，保留旧缓存并提醒重新授权。

验证范围与撤销

服务端逻辑、SQL 权限、撤销、限流、重复请求、账号隔离和删除用隔离内存 PostgreSQL 验证，不是设备验收。尚需用户实际配置并验证 iPhone / Apple Watch 操作及自动化。这里没有提供未经设备签名验证的 .shortcut 安装包。

令牌泄露时先在个人页撤销，再生成并更新五个快捷指令中的发送项。不要为重试改变已有 requestId 的内容。卸载快捷指令不会删除云端数据；使用个人页明确删除入口。

参考：Apple 官方 [API 请求](https://support.apple.com/guide/shortcuts/request-your-first-api-apd58d46713f/ios)、[Apple Watch 快捷指令](https://support.apple.com/guide/shortcuts/run-shortcuts-from-apple-watch-apd5888b0858/ios)。操作名以设备当前系统语言为准。
